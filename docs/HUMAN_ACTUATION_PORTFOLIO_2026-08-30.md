# Human Actuation Portfolio — 2026-08-30

## Problem

As multiple Flower branches mature, they can converge on human-only membranes: identity, legal terms, publication, relationship/outreach, payment setup, or irreversible disclosure.

Crossing every membrane when encountered would make the Center-holder the system's setup clerk. That contradicts the abundance objective because human attention is a scarce input.

## Law

> **Human-boundary actions must compete with each other for scarce attention. Reaching a membrane does not automatically earn crossing it.**

Rank candidate human actions by decision-changing and regenerative return per unit of human burden.

A useful ordering heuristic is:

`H = (DecisionChangingEvidence x EconomicOptionality x RegeneratedAccess x Reversibility) / (HumanMinutes x Consequence x SetupEntropy)`

This is an ordering aid, not a claim that the terms can be measured precisely.

## Consequences

- Do not activate every seller account merely because it is free.
- Do not complete KYC merely to discover whether demand exists unless KYC is itself the last cheap gate to strong evidence.
- Do not create public repositories for every technically complete experiment.
- Do not ask the Center-holder to choose legal/license terms before that legal surface is required to resolve the next uncertainty.
- Prefer reversible human acts over irreversible ones when information return is similar.
- Prefer a cheaper Validation Surface over an eventual Distribution Surface when both can resolve the current uncertainty.
- Bundle human actions when one identity/setup step unlocks multiple validated organisms, but never use bundling to justify weak branches.

## Validation Surface correction

The portfolio must not assume that the eventual monetization/distribution surface is the cheapest place to validate a product.

For each human actuation ask:

`What uncertainty does this action actually resolve?`

Then choose the least burdensome authorized membrane capable of resolving that uncertainty.

Current example:

`private plugin ZIP -> one real developer`

can answer immediate utility truth more cheaply than:

`vendor/legal setup -> Marketplace upload -> hidden approval -> still need tester access`.

## Proof-freshness gate

A human actuation cannot remain top-ranked if the evidence supporting it becomes stale.

Changed Method Navigator previously passed against IntelliJ 2026.1.4. IntelliJ 2026.2+ moved plugin development to Java 25, so current-target technical truth was explicitly reopened and is being reverified against the current 2026.2.1 line before any external binary share is considered.

This is a Proof Dependency Cone: platform-version changes invalidate compatibility evidence; documentation-only changes do not.

## Stopping rule

When free machine-carried evidence is saturated and the remaining uncertainty requires a human-authorized boundary action, Flower should:

- identify the cheapest surface that can answer the uncertainty;
- rank that action against all other human membranes;
- present/cross only with explicit authorization;
- or park the branch.

It must not fill the gap with feature creep, platform tourism, or unnecessary legal/distribution setup.

## Compact form

`MATURE BRANCH -> NEXT UNCERTAINTY -> CHEAPEST VALIDATION SURFACE -> HUMAN PORTFOLIO RANKING -> ONE JUSTIFIED ACTUATION OR PARK`
