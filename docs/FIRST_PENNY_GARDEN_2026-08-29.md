# First Penny Garden — 2026-08-29

Objective: prove one legitimate external value-return loop before optimizing scale.

The Garden is not allowed to equate current tool access with world priority. Candidates are scored separately for world/economic fit and execution fit.

## Current parallel Nursery

### A. Framer paid plugin
World signal: Framer currently exposes Marketplace/Community discovery; current help says plugins can be published immediately, paid products are supported, and creators retain 100% of plugin revenue. Plugins are small code artifacts that can run inside the editor. Current marketplace contains many broad SEO/link/analytics tools, so a generic checker is not differentiated.

Mutation: `Revenue Path Sentinel` — deterministic local preflight specifically for monetization-critical CTA routes: test/sandbox destinations, dead high-intent links, insecure payment URLs, missing observable internal routes, missing link tracking IDs.

Pros: zero inventory, persistent code artifact, platform discovery, automatic delivery, direct paid artifact, no backend/account requirement inside product, AI can build nearly all of it, very short publish-to-signal loop.
Cons: Framer creator/payment account boundary; must test in actual Framer; niche marketplace; competition adjacent.
State: PRIVATE PROTOTYPE BUILT. Not externally validated.

### B. API marketplace microservice
World signal: API.market says free to list, providers keep 80%, marketplace handles gateway/keys/billing/docs/global payouts, products can be pay-per-use/subscription, and every API receives an MCP endpoint. Providers still need to supply a working endpoint/OpenAPI surface.

Pros: machine-to-machine revenue, metered reproduction, agent discovery, potentially excellent passivity.
Cons: hosting/reliability + provider onboarding; demand for any invented endpoint must be proven; greater build/ops surface than Framer.
State: RESERVE. Do not build until a specific under-supplied endpoint is evidenced.

### C. Amazon KDP micro-publication
World signal: KDP is free to use, pays eBook royalties, KDP Select pays from page reads, and AI-generated content is allowed when disclosed and compliant.

Pros: enormous borrowed distribution/checkout/delivery; persistent artifact; no inventory for eBook.
Cons: weak closure observability before publication, slow feedback, severe content competition, human KDP identity/tax/payment boundary, risk of low-value AI content if creation outruns evidence.
State: RESERVE. Requires demand-specific artifact before build.

### D. Canva template/element royalties
World signal: Canva Creator marketplace pays royalties based on usage and exposes creator analytics, but Template Creator currently requires application/acceptance.

Pros: huge platform usage, algorithmic/marketplace discovery, persistent artifacts, royalties.
Cons: application membrane and visual portfolio; slower first external test.
State: RESERVE.

## Why A currently receives one build breath

Not because Framer is familiar. It currently minimizes the full causal distance:

`AI creation -> persistent artifact -> platform distribution -> automatic delivery -> paid transaction -> observable revenue`

while preserving $0 upfront capital and low continuing human labor.

This earns ONE Nursery build/test breath, not Orchard status. If fresh-project testing fails, publishing friction is materially worse than stated, or Marketplace demand is absent, resources rotate.

## Phi reproduction ladder

The money target is deliberately small. After the first verified return, practical milestones use Fibonacci-like rounded phi pressure:

$0.01 -> $0.02 -> $0.03 -> $0.05 -> $0.08 -> $0.13 -> $0.21 -> $0.34 -> $0.55 -> $0.89 -> $1.44 -> ...

The economic invariant is not the numbers; each stage asks whether the causal loop can reproduce with no proportional increase in human burden.

## Closure rule

A published listing is not Fruit. A click is not Fruit. A first paid transaction is F4 financial return. A second independent transaction begins evidence of reproduction. Repeated transactions with negligible human intervention approach F6.
