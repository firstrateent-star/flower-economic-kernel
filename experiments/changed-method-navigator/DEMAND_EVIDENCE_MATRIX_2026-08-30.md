# Changed Method Navigator — Demand Evidence Matrix — 2026-08-30

## Purpose

Prevent positive evidence from being collapsed into one vague `demand exists` claim. The evidence currently supports different dimensions with different strength.

## Evidence vector

### Current problem persistence — strong relative signal

One IntelliJ user described an Eclipse-style method-oriented Git compare outline in January 2026: changed methods listed above the diff, click a method to focus review, especially useful for reviewing changes made by the developer or AI before commit.

The same account resurfaced in a Git Assistant discussion in July/August 2026 asking whether the plugin could show changes per method and focus only the selected method. The plugin author said no. The user rejected Structure/Local History as non-equivalent and continued to describe method-focused diff review as highly valuable.

Interpretation:

- current need is not a one-day impulse;
- persistence across roughly seven months is strong;
- breadth contribution remains one current user.

### Historical independent problem-family breadth — present

JetBrains community discussions from 2003 contain multiple independent developers asking for Java-centric structural diffing: reporting new/changed methods rather than raw changed lines, method-level diffing, and plugin/IDE support for structural comparison. Multiple participants independently endorsed the idea.

JetBrains' long-running structure-aware diff issue later accumulated independent comments asking for semantic/method-aware diff behavior and referencing Eclipse structural compare.

Interpretation:

- the problem family has existed across many independent developers and many years;
- this is evidence of structural breadth/persistence, not proof of a current 2026 market size.

### Adjacent workflow validation — strong category evidence

GitHub added changed-method/function navigation to pull-request review in 2017, explicitly framing review time and understanding changed code as the problem. This proves that method-oriented navigation can be valuable enough for a major review platform to productize.

Interpretation:

- validates the transformation class;
- does not establish IntelliJ plugin demand or willingness to pay.

### Current substitutes — partial, no bounded exact match found

Current bounded scan includes:

- Git Scope: high-download adjacent VCS navigation/review plugin;
- Git Change Highlighter: current changed-code highlighting;
- Topias: historical method-change analytics, stale relative to current IDE;
- SigMap: broad code-intelligence/context platform with method impact and PR blast-radius capabilities, but current JetBrains plugin UI does not expose the narrow local-change -> changed-method list interaction.

Interpretation:

- category is not empty;
- broad method/code intelligence is competitive;
- narrow zero-setup local method navigation remains sufficiently differentiated for a probe;
- no uniqueness claim is warranted.

## Current evidence geometry

The strongest statement supported is:

> A persistent, independently recurring problem family exists around method-aware review/navigation, and the narrow local-change workflow remains unresolved enough to justify a small current-user utility probe.

The evidence does **not** support:

> There is a broad current market for this plugin.

## Cheapest next evidence

After exact-current IDE compatibility is green, the lowest-activation decision-changing probe is a privately authorized direct beta to a high-fit independent IntelliJ developer using IntelliJ's Install Plugin from Disk flow.

Marketplace distribution should be tested only after utility truth earns distribution setup.
