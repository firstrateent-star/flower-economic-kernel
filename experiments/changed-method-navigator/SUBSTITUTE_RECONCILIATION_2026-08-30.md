# Changed Method Navigator — Substitute Reconciliation — 2026-08-30

## Why this check exists

Before asking for a human-authorized Marketplace probe, Flower searched for current substitutes that might have invalidated the surviving niche after the original demand evidence was collected.

## SigMap — partial substitute, not direct workflow replacement

Observed current state on 2026-08-30:

- SigMap core supports Java among its language set.
- Its core/CLI/MCP exposes diff context, per-symbol method impact, method-level call graphs and PR method-blast / blast-radius analysis.
- SigMap also has a current JetBrains Marketplace plugin.
- The JetBrains plugin's current README describes a health-status widget, SigMap Ask ranked-file tool window, regenerate/open-context/settings/roadmap actions and auto-refresh.
- The JetBrains plugin README does not describe the narrow interaction `current local VCS changes -> exact changed Java methods -> clickable method list`.
- Using SigMap's deeper method-impact capabilities requires the broader SigMap CLI/context-engine workflow rather than the same zero-purpose-change local navigation surface.

Interpretation:

SigMap is important adjacent substitution and strong evidence that method-aware code review/context is an active technical category. It does **not** justify claiming Changed Method Navigator is unique, and it does reduce the value of expanding into broad method-impact or AI-context intelligence.

It does not currently invalidate the narrower preflight hypothesis.

## JetBrains 2026.2 upstream check

IntelliJ IDEA 2026.2 is current as of this check. Official 2026.2 release notes were searched specifically for VCS/Diff changes that would collapse the Changed Method Navigator problem into built-in IDE functionality.

Observed VCS/Diff changes include toolbar redesign, conflict indicators, diff type switching, Jump to Source fixes and other diff/merge usability work. No current release-note evidence was found for a built-in outline that enumerates the Java methods touched by current local changes and provides direct method navigation.

Absence from release notes is not proof the capability is impossible elsewhere in the IDE, so this remains counterevidence search rather than a uniqueness claim.

## Scope-defense conclusion

The surviving market probe should stay intentionally small:

`LOCAL VCS LINE CHANGES -> JAVA PSI METHODS -> CLICKABLE IDE-NATIVE METHOD LIST`

Do **not** react to SigMap by adding:

- broad codebase indexing;
- MCP;
- AI context generation;
- call graphs;
- blast-radius scoring;
- PR review reports;
- many-language support;
- generic code intelligence.

Those capabilities belong to a broader competitive field and would increase activation distance before the narrow market uncertainty is resolved.

## Positioning discipline

Do not market the plugin as semantic diff intelligence, AI review, impact analysis, or a replacement for SigMap / IntelliJ's diff viewer.

The honest v0 claim is only that it converts IntelliJ's current local line-oriented Java changes into a small method-oriented navigation map.
